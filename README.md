# RS1_BeatTheta

A compact diffusion model, trained entirely on code-generated audio, that produces ambient sound textures for
theta-range binaural-beat sessions. A binaural beat can be laid on top of the texture with a single argument.

- Model: class-conditional diffusion, about 5.2M parameters, 8 kHz output
- Textures: `warm_pad`, `deep_drone`, `ocean_swell`, `soft_rain`, `crystal_pad`
- Training data: 100% synthetic, generated by code (no recordings, no third-party audio)
- Published model: https://huggingface.co/Rumiii/RS1_BeatTheta (gated; request access on the model page)
- License: MIT

## Project flow

```
 STEP 1            STEP 2          STEP 3              STEP 4            STEP 5             STEP 6
 synthetic   -->   model     -->   diffusion     -->   export      -->   evaluate     -->   generate
 dataset           (U-Net)         training            (AutoModel)       (3 checks)         + binaural beat
 data.py           model.py        diffusion.py        export.py         evaluate.py        generate.py
                                   train.py                              binaural.py        app.py
```

Each step has its own file, so you can read, change or replace one part without touching the others.

## Quick start

Use the published model (after access has been granted, log in with `huggingface-cli login`):

```python
import soundfile as sf
from transformers import AutoModel

model = AutoModel.from_pretrained("Rumiii/RS1_BeatTheta", trust_remote_code=True)   # add .to("cuda") for GPU
audio = model.generate("ocean_swell", seconds=20, beat_hz=6.0)                       # stereo, 6 Hz theta beat
sf.write("session.wav", audio, model.sample_rate)
```

Or train your own and use it the same way:

```bash
python train.py                                   # writes outputs/rs1_beattheta
python evaluate.py --model outputs/rs1_beattheta
python generate.py --model outputs/rs1_beattheta --texture ocean_swell --seconds 30 --beat 6 --out session.wav
python app.py --model outputs/rs1_beattheta       # browser interface
```

A quick pipeline check that finishes in about a minute on CPU: `python train.py --smoke`.

## How the code works, step by step

### Step 1: Synthetic dataset (`rs1_beattheta/data.py`)

Every clip is rendered by a small function for one texture family. Random parameters (root pitch, detuning, slow
modulation rate, noise colour, filter cutoff) make each clip different. Clips are 16,384 samples at 8 kHz (about 2.05
seconds) and are normalised to an rms of 0.2.

```python
def warm_pad(n, rng):
    root, y = rng.uniform(55, 98), np.zeros(n)
    for ratio, amp in zip([1, 1.5, 2, 3, 4, 5], [1, .6, .5, .3, .2, .1]):
        for _ in range(3):
            freq = root * ratio * 2 ** (rng.uniform(-9, 9) / 1200)          # random detune in cents
            y += amp * _slow_lfo(n, rng, .05, .25, .5) * np.sin(2 * np.pi * freq * _time(n) + rng.uniform(0, 6.28))
    return _normalise(_lowpass(y, 1500))
```

The default dataset is 5 textures x 600 clips = 3,000 clips, about 1.7 hours of audio, built in memory in seconds.

### Step 2: Model (`rs1_beattheta/model.py`)

A small 1-D U-Net with five resolution levels. The texture label and the diffusion step are combined into one condition
vector that scales and shifts every residual block (FiLM). A self-attention layer sits at the lowest resolution. One
extra label slot means "no label", which enables classifier-free guidance at generation time.

```python
cond = self.tproj(timestep_embedding(t)) + self.cemb(y)      # diffusion step + texture label
```

### Step 3: Diffusion training (`rs1_beattheta/diffusion.py`, `train.py`)

Clean audio is mixed with noise at a random step. The network learns to predict the velocity `v` (v-prediction).

```python
xt = ab.sqrt() * x0 + (1 - ab).sqrt() * noise              # noisy input
v  = ab.sqrt() * noise - (1 - ab).sqrt() * x0              # what the model must predict
```

The training loop in `train.py` adds the practical pieces:

| Piece | Where | Purpose |
|---|---|---|
| Label dropout (10%) | `labels[...] = len(TEXTURES)` | lets the model also learn an unlabelled prediction for guidance |
| AdamW, warm-up, cosine decay | `lr = ...` | stable optimisation |
| Mixed precision (GPU only) | `torch.autocast`, `GradScaler` | speed and memory |
| Gradient clipping | `clip_grad_norm_` | stability |
| EMA weights | `pe.mul_(decay).add_(...)` | smoother final model; the EMA copy is what is exported |
| Checkpoint and resume | `save_state`, `--minutes` | training can be split over several short sessions |

### Step 4: Export (`rs1_beattheta/export.py`)

Writes `model.safetensors`, `config.json`, the two model code files from `hf/` and the model card into one folder. That
folder loads with `AutoModel.from_pretrained(folder, trust_remote_code=True)` locally or after upload to the Hub with
`python hf/push_to_hub.py --folder outputs/rs1_beattheta --repo-id <user>/RS1_BeatTheta`.

### Step 5: Testing and evaluation (`evaluate.py`, `rs1_beattheta/binaural.py`, `tests/`)

`python evaluate.py --model <folder>` runs three checks and saves listening samples:

1. Loudness: generated clips should sit near the training level (rms about 0.2).
2. Spectrum: log-spectral distance (LSD) between generated clips and fresh procedural clips, printed next to the noise
   floor, which is the LSD between two independent batches of real procedural audio. Tonal textures such as the pads
   use a random root note per clip, so even real clips differ from each other in their average spectrum. A model score
   should therefore be read against its own floor, not against a fixed number. The verdict rule in the script
   (LSD at most twice the floor plus 1 dB) is a practical heuristic, not a validated standard.
3. Binaural beat: stereo audio is generated at 4, 6 and 8 Hz and the beat is measured with a Hilbert transform around
   the carrier tone. The error should be a small fraction of a hertz.

Listening to the saved WAV files remains the final test of sound quality.

`pytest tests` runs five fast CPU tests: dataset shape and level, diffusion target, model forward pass, weight parity
between the training model and the exported Hub model, and beat accuracy of generated audio.

### Step 6: Generation and the binaural layer (`hf/modeling_rs1_beattheta.py`, `generate.py`, `app.py`)

`generate()` works in four parts:

1. Sample several 2-second clips with DDIM-style deterministic sampling and classifier-free guidance.
2. Stitch them with equal-power crossfades to the requested length.
3. If `beat_hz` is set, remove bed energy around the carrier with a band-stop filter, then add two sine tones. The
   left tone is `carrier - beat/2` and the right tone is `carrier + beat/2`, so the right minus left difference equals
   the requested beat exactly. A slow fade in and out is applied.
4. Return mono audio, or stereo with the beat.

```python
left  = tone_level * np.sin(2 * np.pi * (carrier_hz - beat_hz / 2) * t)
right = tone_level * np.sin(2 * np.pi * (carrier_hz + beat_hz / 2) * t)    # right - left = beat_hz
```

The beat is signal processing and is never learned, which is why it can be verified. The neural model only provides the
ambient texture. `python app.py` wraps all of this in a browser interface with a spectrogram.

## Reference run

The published model was trained on a single NVIDIA T4 (Kaggle):

| Item | Value |
|---|---|
| Dataset | 3,000 synthetic clips (5 textures x 600), about 1.7 hours |
| Parameters | 5.18M |
| Steps | 12,000, batch size 24 (about 96 passes over the data) |
| Training time | about 36 minutes |
| Training loss | 0.68 at the start, about 0.08 at the end (v-prediction MSE) |
| Generated loudness | rms 0.16 to 0.19 across the five textures (training level 0.2) |

Note on provenance: the published weights were trained with an earlier single-file version of this code. The files in
this repository are a cleaned-up refactor with the same architecture and recipe. Weight compatibility between the two
model definitions is covered by the parity test, but a full-length training run with the refactored scripts has not been
done. The smoke run (`python train.py --smoke`), the evaluation script and the tests were run on CPU.

## Limitations and honest notes

- Output is 8 kHz. Longer audio is built by crossfading short generated clips, so very long sessions may show repetition.
- Textures only. There is no music or speech.
- Sound quality has been checked by loudness and spectral measurements and by listening to samples; there is no formal
  listening study.
- Binaural-beat effects vary between people and the research evidence is mixed (see references). The project makes no
  medical claims.
- The Hugging Face repository is gated. Anyone can train an equivalent model from this code.

## Safety

Use stereo headphones at a comfortable volume. Do not listen while driving or operating machinery. Ask a doctor first if
you have a seizure disorder or heart condition, or are pregnant. This is not a medical device or treatment.
